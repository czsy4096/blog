Arch Linuxにはユーザーによって投稿されたスクリプトを使って公式リポジトリにないソフトウェア等をインストールできる[AUR (Arch User Repository)](https://aur.archlinux.org/)という仕組みがあります。膨大な数のパッケージが登録されており、Arch系ディストロの大きな魅力となっていますが、通常の方法でAURからパッケージをインストールするにはいくつものコマンドを叩く必要があり煩雑であるほか、pacmanのチェック対象でないため自分でアップデートをチェックしなければならないなど面倒な点が数多くあります。そこでAURのパッケージ作成・インストールなどを自動化し、pacmanの感覚で扱えるようにする[AURヘルパー](https://wiki.archlinux.jp/index.php/AUR_%E3%83%98%E3%83%AB%E3%83%91%E3%83%BC)というソフトウェア群を利用することが定番となっています。

## AURヘルパー・paru

[paru](https://github.com/morganamilo/paru) は比較的新参のAURヘルパーで、メインの開発者は元々 [yay (たぶんいちばん人気があるヘルパー)](https://github.com/Jguer/yay) の開発に参加していたが、新機能の導入などに非常に慎重なyayから離れてparuを開発したとしています。

インストールは[AUR](https://aur.archlinux.org/packages/paru)から。Rust製なのでrustかrustupが必要ですが、開発者でなければどちらでも構わないはず。ちなみにEndeavourOSだとOS側が用意したアップデートチェッカーがyayかparuを使用するようになっており、EndeavourOSの独自リポジトリからビルド済みのパッケージをインストールできます。

使い方はyayと同様にpacmanのコマンドをそのままparuに置き換える感じで問題なく、PKGBUILDのダウンロードだけを行う -G 系列のオプションがあったりする模様です。あとは `paru` だけで起動するとシステムアップデート (-Syu) になったり、 `paru (検索語句)` とオプションをつけずに起動するとパッケージの検索からインストールまでできるインタラクティブモードになったり便利機能があります。

## paruの設定ファイル

AURまたはEndeavourOSのリポジトリからparuをインストールすると基本の設定ファイルが `/etc/paru.conf` にインストールされます。普通にini型の設定ファイルです。これを直接編集しても良いですが、パッケージのファイルをあまり書き換えたくないとかユーザーごとの設定をしたいという場合には他に設定ファイルを用意することができます。環境変数`PARU_CONF` > `$XDG_CONFIG_HOME/paru/paru.conf` > `$HOME/.config/paru/paru.conf` の順にファイルを探して最初に見つかったものを読み込む感じになるようです。普通にインストールされたLinuxだと `~/.config/paru/paru.conf` を作れば良いかと思います。

### 設定ファイルのInclude

paruは最初に設定ファイルを見つけると、それ以降は設定ファイルを探しません。すなわち、ユーザーごとの設定ファイルを作る際はデフォルトの設定ファイルを所定の場所にコピーして使うというのが基本となっているのですが、「デフォルト設定にいくつか設定を付け足す」というような設定のやり方をしたい場合は他のファイルを読み込むよう指示する書き方があります。すなわち、
```toml
[options]
Include = /etc/paru.conf
```
というように書くことで `/etc/paru.conf` を読み込むことができます。一番上に書くのがいいと思います。

### その他便利な設定

個人的に特記するような設定項目としてはまず "BottomUp" で、パッケージの検索時に並びが通常の逆順になります。検索で多くのパッケージがヒットした際などにかなり見やすくなります。ただpacmanにはないオプションなのでpacmanと併用する場合は混乱するかもしれません。あとは "SudoLoop" を有効にしておくと、paru起動時にsudoパスワード入力 → ビルドに時間かかる → インストール時にもう一度sudoパスワード要求される、ということがなくなります。

私が以前使用していた[trizen](https://github.com/trizen/trizen)でAURパッケージをインストールしようとすると、PKGBUILDなどをダウンロードして一つ一つ表示しつつ編集の要不要を尋ねて必要ならEDITORのエディタで編集、という流れになります。paruデフォルト設定だとPKGBUILDなどをダウンロードしてlessで表示(カラー対応版のcatといえるbatをインストールしているとbatで表示)してこれでいいですか?となります。ただ標準出力に出して表示しているので編集したくなってもできないのが問題です（「これではだめだ」というときにはインストールをキャンセルするしかない）。編集をする場合にはファイルマネージャーでのレビューを有効にする必要があり、追加オプションで `--fm=(使うファイルマネージャー)` とするのですが、毎回自動で行う場合には設定ファイルの \[bin\] セクションに `FileManager = (使うファイルマネージャー)` と書きます。使うファイルマネージャーはコンソール式のものが使用でき、例えば[Vifm](https://vifm.info/)、[nnn](https://github.com/jarun/nnn)、[ranger](https://github.com/ranger/ranger) などが有名どころでしょうか。PKGBUILDなどをダウンロードした一時ディレクトリがファイルマネージャーで開かれるので適宜ファイルを編集します。ただし、このときの編集をインストール時に反映するためには \[options\] セクションで "SaveChanges" オプションを有効にしておくのも合わせて必要です。例えば現在私が使用している[yazi](https://yazi-rs.github.io/)なら
```toml
[options]
SaveChanges

[bin]
FileManager = yazi
```
という風に書けばOKです（上記は必要部分だけの抜粋なのでこれだけコピーしても動きません）。
